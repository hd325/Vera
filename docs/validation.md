# Vera 公開版驗證記錄

2026-11-21。檢查使用公開副本與合成資料，未修改原開發目錄或連接真實帳號資料。

## 本次修復

- 將舊 DeepSeek 測試遷移至目前的 MaaS 模型介面；檔案意圖由模型規劃，移除已過時的關鍵詞路由測試假設。
- 更新全文索引、文件指紋、上傳分類證據與介面資源清單的測試；保留跨帳號、待審、刪除與引用權限斷言。
- 修復索引工作執行器不能接收參數的缺陷；AI 規劃請求恢復 HTTPS 憑證驗證，兩者均新增回歸測試。
- 文件工具改用 PyMuPDF 正式匯入介面，避免相容性警告污染子程序通訊；補齊上傳超限錯誤代碼及「其他」資料名稱驗證。
- 接入回答過程展示，維持 Markdown 清理、來源每次重驗證、會話切換隔離與有限頁面 PDF 預覽。
- 升級華為 SDK、ASN.1、檔案鎖與其他可修復的間接依賴，保留相容性限制。

## 驗證方式

- 完整 Python 測試在獨立的臨時資料目錄執行，不需要真實密鑰；不透過跳過或停用測試消除失敗。
- 升級依賴後，本機完整 449 項測試通過：0 失敗、0 錯誤、0 跳過，包括新增的工作執行器傳參與規劃器憑證驗證回歸。
- 完整正式前端的 11 項離線瀏覽器檢查涵蓋登入、手機布局、內容注入、來源撤權、會話切換、原檔隔離、PDF、私人記憶與回答過程。所有網路請求由測試攔截，不接觸正式後端或供應商。
- 已檢查空密鑰啟動、無預設帳號、依賴一致性、待發布檔案中的已知私人資料；使用 Gitleaks 檢查發布內容與公開 Git 歷史。
- GitHub Actions 在 Windows 與 Linux 重新安裝核心和選裝依賴，再執行完整回歸。[查看對應提交的實際結果](https://github.com/hd325/Vera/actions/workflows/tests.yml)。上傳成功本身不代表檢查通過。

## 依賴掃描限制

依賴掃描從 37 條通報降至 6 條（掃描資料含重複項），涉及 Chroma 與華為 SDK 固定依賴的 PyMongo。去重後為 5 項通報，不能宣稱「依賴零漏洞」。

Chroma 通報針對本應用未啟動的獨立 Chroma 伺服器及管理介面；PyMongo 通報針對本應用未使用的非 bytes BSON 解碼輸入。詳細適用邊界、固定版本及持續追蹤事項見 [SECURITY.md](../SECURITY.md)。若部署方式改變，必須重新評估。

## 未驗證範圍

未使用真實 MaaS、OCR、搜尋或微信憑證呼叫供應商，未對線上伺服器進行滲透或壓力測試，也未驗證 2 核／2 GB 主機的實際並發人數。本次局部安全回歸不等同完整外部安全審計；舊版本報告不可套用為新版安全通過證明。
